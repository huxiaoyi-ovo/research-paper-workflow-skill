# Reviewer Response Workflow

## Step 1 — reconstruct the review exactly
Preserve original order, wording, categories, and supplied references. Keep verbatim quotations visually distinct from author paraphrases; do not silently correct substantive wording or notation inside a quote.

If positive/descriptive comments are omitted, explain why numbering may be non-consecutive.

## Step 2 — build the response matrix

| Field | Question |
|---|---|
| ID | What is the original identifier? |
| Surface request | What did the reviewer literally ask? |
| Underlying concern | What decision concern is behind it? |
| Original manuscript | What did v1 actually say/do? |
| Evidence available | What evidence already exists? |
| Action type | Clarify / edit / analyze / experiment / narrow scope |
| New work? | Is this revision-new? |
| Manuscript state | What changed, or what already addresses the concern? |
| Response claim | What can we safely say? |
| New-question risk | Could this answer create another concern? |
| Location | Where can the reviewer verify the answer in the revised manuscript? |
| Closure status | Open / partial / closed / not actionable |

## Step 3 — answer in the right order
1. direct answer;
2. strongest evidence;
3. manuscript state;
4. location.

If the manuscript already contains the answer, cite its location and record that the text was unchanged. If a necessary explanation is missing, add it to the manuscript before closing the concern.

When reviewers request incompatible changes, identify the conflict, follow explicit editor instructions, and explain the same scientific rationale consistently in both replies.

## Step 4 — calibrate tone
Do not over-defend. If evidence is sufficient, state it and stop.

Check the venue's response length and file-format limits before finalizing, and preserve traceability to the original comments if the reply must be shortened.

## Step 5 — verify against manuscript
Every “we revised / added / clarified” statement must be true in the final manuscript.
